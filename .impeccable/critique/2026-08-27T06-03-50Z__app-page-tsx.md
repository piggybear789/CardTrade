## Anti-Patterns Verdict

**LLM assessment.** Not AI slop. The shell is competent product UI — one typeface, fixed rem scale, a real token layer, a docked rail. A Linear/Stripe-fluent user would trust the chrome and distrust the content. The register breaks are *strangeness without purpose*, not over-decoration:

- `FilterCheckRow` (CatalogControls.tsx:527-562) is a `<button aria-pressed>` inside a `<fieldset>/<legend>` that promises checkboxes. Unselected state is a 6px dot at 50% alpha (2.18:1); selected adds a trailing `ChevronRight` that means "drills in" everywhere else on the web.
- Two search fields with identical affordance and opposite scope: `HeaderSearch` queries the server, `CatalogFilterSearch` filters only rendered items (CatalogControls.tsx:109-111).
- Visual weight inverted: the obsidian "All" *category pill* (GenrePills.tsx:478) carries the same weight as "Create New Listing".
- `--action: 41 94% 50%` is defined at globals.css:44 as "bright amber: this is your move", a `variant="action"` button exists — neither appears on this page.

Banned-pattern hits: **tiny uppercase tracked eyebrows** — `.market-label` (11px/600/uppercase/0.12em) stacked five times in one 304px rail (MARKETPLACE, SORT, CONDITION, PRICE, AVAILABILITY). **Ghost card latent** — base `Card` is `border` + `shadow-market` (30px blur); the catalog tile opts out, but the primitive violates it. Clear on: side-stripes, gradient text, glassmorphism, radius ≥32px, overflow.

**Deterministic scan.** `detect.mjs` over `app` + `components`: 4 findings, all `broken-image` in `components/ui/storage-image.tsx` (lines 11, 19, 35, 46). **All four are false positives** — every hit is the literal string `<img>` inside a doc comment, not JSX. The real `<img>` at line 52 is unflagged, though it does carry a genuine latent empty-src path via the ternary at line 49.

The irony is the finding: the detector fired four times on the word "broken image" in prose and completely missed the actual broken-image-looking element on the page, because `ItemCard.tsx:130` renders a lucide `ImageOff` component rather than an `<img>` tag. Precision 0/4, and a miss on the thing a human sees first.

**Visual overlays.** Not available — no browser automation in this session, no dev server running. Evidence is the user-supplied 1536px-viewport screenshot plus existing Playwright captures in `ux-review/captures/`.

## Overall Impression

The page is not badly styled. It is badly *stated*. Every craft signal is present — disciplined tokens, one typeface, deliberate cross-gutter baseline alignment, a non-linear price ladder that commits on release — and none of it is spent on the two jobs this page now has: sell one item convincingly, and prove the platform is safe.

The single biggest opportunity is that the two worst problems solve each other. There is ~947px of dead cream to the right of the only listing, and the entire trust proposition (Stripe, escrow, two-sided collateral, dispute resolution) currently exists only inside a `<meta description>`. Put the second thing in the first thing.

## What's Working

**Cross-gutter baseline alignment, done deliberately.** The rail `<h1>` (MarketplaceShell.tsx:152) and the content `<h2>` (CatalogResults.tsx:77) both resolve to `text-head` with matching `md:py-7` insets, so their first baselines land on the same line across a 304px boundary. Rare enough to be clearly intentional.

**URL-as-state with correct concurrency.** `writeCatalogUrl` and `browseCurrentFromSearch` are true inverses, `popstate` is handled, first paint is server-rendered so `/?category=Pokémon&condition=Mint` SSRs correctly, and `runFetch` carries a generation guard (fetchGen, CatalogView.tsx:119/132) that discards stale responses. The out-of-order-response bug is pre-empted rather than discovered in production.

**Genuine restraint at the token layer.** One typeface including numerics via `tabular-nums` as a font feature rather than a mono import. `--trust` teal documented as "reserved for verified identity and provenance, never decoration". A single `--border` hairline with an explicit ban on inventing a second cream. Body text clears contrast comfortably — muted-foreground on background is 6.16:1, gold price text on card is 6.14:1. The system is more disciplined than most shipped design systems; the page under-spends it.

## Priority Issues

### [P0] The focus indicator fails WCAG 2.2 AA product-wide
`focus-visible:border-gold/40` is a 1px border at 40% gold: **1.78:1** against the page background, 1.83:1 against the rail. SC 1.4.11 requires 3:1. It appears in ~70 component files including every control on this page, and it is a documented system decision (globals.css:30-37).

**Why it matters:** keyboard-only and low-vision users cannot see where they are, on a site where the next click commits money.

**Fix:** keep the edge philosophy, raise contrast. Solid `--gold` clears 3:1 (5.46:1 on background). `focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-1 focus-visible:outline-gold` avoids the 1px reflow risk on controls that don't pre-reserve a border. Then collapse `GenrePills.tsx:213,245` onto it and switch `select.tsx:37` from `focus:` to `focus-visible:`.

**Suggested command:** `$impeccable audit`

### [P0] The desktop empty-photo state renders as breakage
`ItemCard.tsx:129-132` renders lucide `ImageOff` — the universal "image failed to load" glyph — on flat `bg-muted` at `md` and up. Two lines above, the phone branch uses `ListingPhotoEmpty`, whose own doc comment (ListingPhotoEmpty.tsx:6) says it exists to be "a card-shaped absence, **not a broken-image slash**." The desktop branch does exactly the thing the mobile component was written to avoid.

**Why it matters:** on a marketplace where the photo is the goods, "broken" and "no photo" are opposite signals. With one listing, this glyph is 100% of the inventory impression.

**Fix:** delete the `md:flex` branch and let `ListingPhotoEmpty` render at every width: `<ListingPhotoEmpty title={item.title} compact={inMosaic} />`.

**Suggested command:** `$impeccable polish`

### [P1] No low-count grid state; one card in an 81%-empty row
`CatalogGridBody` (CatalogResults.tsx:195-199) branches only on `total === 0`. `CATALOG_TILE_GRID` (catalogGrid.ts:26) resolves at `lg` to `repeat(auto-fill, minmax(13rem, 1fr))`. At the captured 1536px viewport the content column is ~1168px, yielding 5 tracks of ~221px; one is filled and ~947px is dead cream. `max-w-workspace` is 90rem, so a wide monitor gets six tracks and five holes. `auto-fit` would be worse (one card stretched to 1168px). Neither is a designed state.

**Why it matters:** this is the state a new marketplace lives in for its entire launch window, and it is now the homepage. Emptiness at this scale reads as abandonment.

**Fix:** branch on low counts and spend the recovered space on the trust story that is currently homeless — tiles left, a "How NoDitto protects this deal" panel right.

**Suggested command:** `$impeccable onboard`

### [P1] A failed filter fetch leaves the UI silently lying
`apply` (CatalogView.tsx:153-163) calls `setCurrent(next)` and `writeCatalogUrl(next)` *before* `runFetch`. On failure, `runFetch` hits `if (!fetched.ok) return;` at line 135 after `setPending(false)`. Net result: the URL says `?condition=Mint`, the rail shows Mint checked, the grid shows unfiltered results, the spinner stops, and nothing tells the user. The mobile scroll path handles the identical failure correctly with a retry (CatalogInfiniteGrid.tsx:123-127, 236-242).

**Why it matters:** a buyer believes they are seeing only Mint cards when they are not. That is a false statement about inventory, not a UI blemish.

**Fix:** add an error branch that reverts `current` to `settled`, restores the URL, and surfaces the retry already written in `CatalogInfiniteGrid`.

**Suggested command:** `$impeccable harden`

### [P2] The same concept is stated six times above the fold
"Marketplace" in the header nav (gold-underlined as current), "Marketplace" as the rail `<h1>`, "MARKETPLACE" as the rail group eyebrow, "Browse All" as the active rail link, "All Listings" as the content `<h2>`, "All" as the first pill. A seventh lives in the a11y tree as `role="region" aria-label="All Listings"` duplicating the `<h2>` it contains. Three are the literal word "Marketplace" in three type treatments within 200 vertical pixels — and the rail `<h1>` and content `<h2>` are the same size and weight.

The code is self-aware in the other direction: MarketplaceShell.tsx:13-15 and 120-124 both explain why the *mobile* header was removed to avoid "the same page titled twice, one line apart." The mobile double-naming was fixed; a desktop triple-naming shipped.

**Fix:** drop the rail `<h1>` (the header nav already marks Marketplace current) and promote "All Listings" to `<h1>`; suppress the group eyebrow when a group has ≤2 links on its own page; drop the "All" pill and let an unselected row mean all.

**Suggested command:** `$impeccable distill`

## Persona Red Flags

**Jordan (confused first-timer):** Sees one item and concludes the marketplace is empty — but it is region-scoped (page.tsx:95) and `CatalogResultCount` renders a bare "1 listing" with no qualifier. `EmptyRegion` explains region scoping in full prose, *but only when the count is zero*. The product explains itself at 0 and goes silent at 1. Cannot distinguish the header search from "Filter…"; typing a card name into the latter yields a bare `<p>` with no icon and no way out.

**Sam (screen-reader / keyboard-only):** Focus is 1.8:1 at 1px. Heading navigation goes `h1` Marketplace → `h2` **Refine results** → `h2` All Listings, because `<aside>` precedes `<section>` in DOM order — the controls are announced before the thing they control. `CatalogResultCount` carries `aria-live="polite"` but is mounted inside `hidden sm:block` (CatalogResults.tsx:80), and a `display:none` live region never announces. Category pills use `aria-pressed` for mutually exclusive behaviour; should be `role="radiogroup"`.

**Riley (stress tester):** Back doesn't work — six filter changes then Back exits the page. `/?category=Pokémon&category=Gundam` is parseable and filterable but renders as "All Listings" with "All" active. Selecting a category pill produces no removable chip and no "Clear all", because `hasActiveFilters` (CatalogControls.tsx:215-220) and `hasFilters` (:467-472) both omit `categories`. A client filter string survives pagination and silently hides results on the new page.

**Marcus (consignment-grade collector, project-specific):** Holds a PSA 10 worth ~$8,000 and wants to know who is here, how money moves, and what happens if it arrives cracked. The homepage answers none of the three. The only trust artefact is a 16px unlabelled shield — `IdentityBadge` supports "ID verified · {name}" via `iconOnly={false}` and the tile declines it. Condition is the largest block in the rail and never appears on the tile; for graded cards that is the entire price argument. The title truncates to one line on the *widest* screen (`md:truncate`, ItemCard.tsx:158) while the phone gets two.

## Minor Observations

- `--action` amber is defined and unused; the primary CTA is obsidian.
- The loading skeleton draws a filter-field placeholder that the loaded page only mounts when `total > 0`.
- The page background paints a horizontal rule every 4rem at 1.8% alpha — below the perceptual floor. Same for the rail's 28px/4.5% shadow.
- `Input` has no hover or `aria-invalid` state while the pill beside it does, so hovering across the content header gives feedback on one control and not its neighbour.
- `Breakpoint.tsx:9` names the `md` query `LG_QUERY`, and comments throughout MarketplaceShell say "below `lg`" while classes say `md:`.
- "Refine results" (CatalogControls.tsx:367) appears *after* the Sort block with rules above and below, so it reads as a divider caption rather than a heading for the controls under it.
- `.market-label` at 0.6875rem is an 11px seventh size outside the scale that tailwind.config.ts:123 calls "the ONE place a text size is decided".
- The mobile mosaic (`balanceMosaicColumns`, catalogGrid.ts:113-136) is genuinely well-engineered and should not be refactored away.

## Questions to Consider

1. If the catalog is the homepage, why does the catalog assume a full catalog? Every state is "zero" or "many". What would this page look like if you designed the 3-listing state first and let 300 be the variant?
2. What if the empty space is the product? 947px of dead row and a homeless trust proposition solve each other.
3. Why does a marketplace for graded cards let you filter by condition and refuse to show it on the tile?
4. Which of the twelve filter controls would you keep if you could keep four?
5. The design system is more disciplined than the page using it. What mechanism catches that next time — a token-usage lint, a states review gate, or designing the sparse state first?
